# EAXAU：AI 量化联盟

状态：AI 量化联盟已作为 EAXAU 主产品建设；六策略展示、选配、EA 商城、USDT 账路与资管接入均按真实能力显式分层。
更新时间：2026-08-24。

## 已确认的产品决策

- 产品名称统一为“AI 量化联盟”，是持续运行的正式资管服务，不使用“限时资管”“Managed Session”或“Managed Vault”作为客户产品名称。
- 首页固定提供六款量化策略；每笔委托可从中选择 1–6 款，所选策略权重合计 100%。现有大量 EA 名录保留为独立“EA 商城/资料库”，不占用六个策略席位。
- 客户可选择 1 至 3 家可选执行券商：Exness、IC Markets、Blueberry Markets；不声称任何券商为官方合作方或已为平台背书。
- 开户接入分为客户自行开户 `SELF_OPENED` 和平台协助接入 `PLATFORM_ASSISTED`。
- 资金路由分为客户直充券商 `BROKER_DIRECT` 和平台代收再划转 `PLATFORM_COLLECTION`；平台代收只允许用于平台协助接入，并受每券商书面许可门控。
- 六策略方案由资金规模、风险预算、策略组合、券商选择、开户接入与资金路由共同组成。
- “系统推荐”“客户手动配置”和“运营协助配置”只是配置来源，不是三种资管产品。
- EA 商品 USDT 收款、客户直充券商、平台代收再划转是三条独立账路，不共享收款地址或到账状态。
- 平台不保存券商密码、短信验证码、API Key、钱包私钥或助记词；平台代收的链上转出在外部企业钱包/多签系统完成，Web 服务只记录审批与 Tx Hash。
- 牛帮继续独立运行。EAXAU 不直连牛帮数据库，也不调用交易引擎内部函数。
- 可复用数据能力通过品牌中立、版本化的 Quant Data Core API 输出；演示数据必须标记为 `DEMO`，不得冒充实盘。

## 当前产品链路

```text
六策略首页
  -> 从六款目录中选择 1–6 款并配置权重
  -> 选择 1–3 家可选执行券商
  -> 选择 SELF_OPENED / PLATFORM_ASSISTED
  -> 选择 BROKER_DIRECT / PLATFORM_COLLECTION（受许可门控）
  -> 建立账户映射、资金意向与事件审计
  -> 核验交易授权后部署策略与持续观察
```

正式首页入口为 `/`，旧 EA 商城保留在 `/market`，兼容预览入口为 `/v2-preview`。策略内容与数据后台为 `/admin/v2-content` 和 `/admin/v2-data`。资管申请、资金意向、收款地址、筛查、对账、动态验证转付、券商入账和异常处理进入各自受控后台流程。

EA 商城仍可由后台把商品设为 `direct`：系统锁定 USDT 报价，客户提交网络与 Tx Hash，管理员核对真实到账后才提供受控流式下载。该商户收款链路与客户资管资金完全分开。

## 真实能力边界

仓库可以实现产品界面、数据契约、资金状态机、地址池、权限、审计和人工运营流程，但不能凭代码生成外部业务资格。上线实际收款与交易前仍需：

- 三家券商的真实客户账户、管理人/MAM/PAMM/交易授权和执行适配；
- 每一家开放平台代收的券商实体分别出具书面许可；
- 企业钱包或托管服务账户、生产 API/Webhook/MPC 策略，或者可审计的人工多签流程；
- 六策略真实账户、数据 Provider、风险参数与实盘验收；
- EA 商品真实商户地址、汇率源、交付文件与退款 SOP；
- 适用地区的合同、KYC/AML、客户资产、会计与税务审阅。

平台代收默认关闭，专用地址默认不复用；付款钱包归属、筛查结果、动态验证、转出 Tx、券商入账和退款/异常必须逐笔留痕。服务器不保存私钥，也不声称已自动接入 BVNK、Cobo 或其他托管服务。具体开户、管理人申请与企业钱包入口见 [资管与 USDT 资金链路](MANAGED_USDT.md)。

未配置外部数据服务时，策略继续使用与正式 API 同结构的确定性 `DEMO` Provider。可设置 `NIUBANG_DATA_URL + NIUBANG_STRATEGY_MAP` 读取牛帮公开策略，也可设置 `QUANT_DATA_CORE_URL` 启用品牌中立 HTTP Provider；读取失败明确显示 `OFFLINE`，不会静默伪装成实盘。
