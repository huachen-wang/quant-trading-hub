# Claude UI 交接：EAXAU AI 量化 V2

本文件用于把 UI 与细节工作交给 Claude 或其他设计实现代理。开始前必须先阅读同目录的 `PRODUCT_ARCHITECTURE.md` 与 `API_CONTRACT.md`。

## 1. 任务目标

做出一条可实际操作的 V2 预览链路：

`六策略首页 -> 策略详情 -> 模式选择 -> 自主分仓配置 -> 校验摘要 -> 账户概览`

第一版接本地 Demo Provider，但组件和查询必须使用 API 契约中的正式 DTO。不得为了方便另造一套只适用于 mock 的字段。

## 2. 不得改变

- 首页恰好六个策略席位。
- 两种业务模式：签约管理、自主分仓。
- 推荐/自定义/运营代配只是配置来源。
- 分仓由平台、策略、资金权重和风险预算组成。
- 桌面端支持拖放，移动端必须有不依赖拖放的完整操作路径。
- 演示数字永久显示 `模拟数据`，不可伪装成实时账户。
- 不修改现有 V1 API、数据库表和线上根路由。
- 不添加下单、平仓、入金或直接修改牛帮参数的按钮。

若 UI 需求与 API 契约冲突，先记录到 `docs/eaxau-v2/OPEN_QUESTIONS.md`，不要静默修改契约。

## 3. 路由建议

```text
/v2-preview                     六策略首页
/v2-preview/strategies/:id      策略详情
/v2-preview/allocate            自主分仓配置器
/v2-preview/accounts            账户总览
/v2-preview/accounts/:id        单账户详情
/admin/v2/strategies            六席位与内容块编辑
/admin/v2/platforms             平台和商业条款编辑
/admin/v2/rules                 分仓规则与推荐模板
```

所有入口先受 `feature_eaxau_v2` 控制。现网导航默认不展示。

## 4. 视觉方向

- 气质：精确、实时、可信、有速度感；更像专业量化终端，不像 EA 商品货架。
- 背景以接近黑色的中性色为主，配合白色、信号绿、琥珀金和少量青色，避免整页只有深蓝色。
- 卡片圆角不超过 8px；不做卡片套卡片，不用漂浮渐变球和大面积紫蓝渐变。
- 六张策略图保持同一摄影/数字艺术体系，但每张有不同场景、色温和运动方向。
- 图片内最多一个短关键词，例如“金戈铁马”；完整策略名、收益和标签放在 HTML 文本层。
- 不在图片上堆典型 AI 文本框、重复标题、平台徽章和多个数值。
- 数字使用等宽或 tabular numerals，涨跌不只依赖颜色，还要有符号与文字。
- 图表先保证轴、单位、数据状态和可读性，再考虑动画。

## 5. 首页布局

### 顶栏

- 左侧只显示 EAXAU 字标。
- 中间为最少量导航：策略、分仓、账户。
- 右侧显示全局数据状态和账户入口。
- 不使用营销缩写堆叠，不用超宽空导航框。

### 组合概览

- 这是数据带，不是 Hero 卡片。
- 显示六策略组合曲线、今日变化、阶段收益、最大回撤和同步时间。
- 高度受控，首屏必须露出至少一整行策略卡。

### 六策略矩阵

- 1440px：3 列 x 2 行；1024px：2 列 x 3 行；移动端：1 列。
- 每卡固定媒体比例和指标区高度，任何名称、加载状态或涨跌变化都不能推动网格。
- 一张卡只保留最重要的 3 至 4 个指标。
- `LIVE`、`DEMO`、`STALE` 状态视觉必须明显，`STALE` 不能继续显示为绿色在线。

### 模式入口

- 使用两段式控件：签约管理 / 自主分仓。
- 选中后显示下一步和关键区别，不新增第三个模式。

## 6. 策略详情

- 顶部：策略短名、状态、风险、数据源、同步时间和进入分仓按钮。
- 主体第一屏：大净值图 + 指标带 + 当前持仓摘要。
- 下方：后台内容块按顺序渲染，可混合图、文、证据、版本、FAQ 和风险说明。
- 试盘内容没有配置时显示“暂未开放”，不放空按钮或坏链接。
- 评论占位必须标记为示例；未来接真实评论时保留来源和发布时间。

## 7. 分仓配置器交互

### 桌面端

1. 选择资金和风险预算。
2. 从平台目录启用最多三个平台桶。
3. 把策略拖入平台桶，或使用策略菜单中的“加入平台”。
4. 用步进器/滑杆调整平台资金权重和桶内策略权重。
5. 右侧摘要实时显示总和、集中度、预计成本和校验问题。
6. 只有权重合计正确且无 `ERROR` 时才允许继续。

### 移动端

- 使用步骤流，不做横向三栏缩小版。
- 平台和策略通过底部选择器添加。
- 每行提供减、输入、加控件；长按拖动可选，但不是唯一排序方式。
- 页面底部固定汇总条，不能遮住最后一项。

### 校验呈现

- `ERROR`：阻止继续，并提供定位到字段的操作。
- `WARNING`：允许确认后继续，确认文本写入审计。
- `INFO`：解释成本、数据缺失或推荐原因。
- 不用弹窗一次性堆全部问题，问题靠近对应平台或策略显示。

## 8. 账户页

### 签约管理

- 强调只读状态、合同技术方、权益、波动、回撤和数据更新时间。
- 不显示“调整仓位”控件。

### 自主分仓

- 显示生效方案版本、平台桶、策略贡献、账户连接和风险预算。
- “调整”创建新草稿，当前生效方案继续可见，不直接覆盖。

## 9. 必备状态

每个页面和组件都要覆盖：

```text
loading
empty
demo
live
stale
offline
permission_denied
partial_data
validation_error
unexpected_error
```

不要用空白页、无限转圈或只有“加载失败”的笼统文案。部分数据可用时保留可用内容，并说明缺失部分。

## 10. Demo 数据要求

- 固定六个策略 ID，数据可重复生成但必须确定性，避免每次刷新收益跳变。
- 至少覆盖一个暂停策略、一个过期数据源、一个无持仓策略和一个部分数据策略。
- 平台至少三家，覆盖低点差、高返佣、较快出金和不同终端兼容性，但所有商业数据标记为示例。
- 分仓推荐至少三份测试夹具，用于低、中、高风险校验；它们不是第三种业务模式。
- 使用真实时间格式和边界值：零收益、负收益、长名称、缺失指标、100% 集中度。

## 11. 性能与实现要求

- 首页只发一个六策略聚合请求。
- 图片按显示尺寸加载并懒加载首屏以下内容。
- 详情内容块按稳定 key 渲染；图表库与富文本编辑器按路由拆包。
- 拖放库必须支持键盘操作；若当前 Expo Web 方案不可靠，先实现可访问的选择/移动控件。
- 所有数值格式化集中到 formatter，不在组件中散落百分比和币种逻辑。
- API 查询键、缓存时间和错误映射集中定义。
- 不把六个策略复制成六套组件；数据驱动一个稳定组件体系。

## 12. 交付与复查

Claude 完成后必须提交：

1. 变更文件清单和不变量说明。
2. 桌面 1440x900、平板 1024x768、手机 390x844 截图。
3. 六策略首页、详情、配置器、两种账户模式的操作录像或逐步截图。
4. TypeScript、lint、单元测试和生产构建结果。
5. 无横向溢出、无遮挡、无布局跳动的检查结果。
6. Demo/LIVE/STALE 状态核对。
7. 没有修改 V1 API、数据库和牛帮执行路径的证明。

UI 评审通过后再决定是否把 `/v2-preview` 提升为正式入口。
